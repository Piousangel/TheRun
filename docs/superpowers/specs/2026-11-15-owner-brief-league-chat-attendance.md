# 오너 브리프: 리그전 · 출석왕 · 실시간 채팅 · 쉬운 가입 (2026-11-15)

- 상태: **오너 요구 + 설계 방향**이다. 구현 스펙이 아니다. 아침 팀이 월요일마다 여기서 큰 기능을 골라 단계별 스펙(`docs/superpowers/specs/`)으로 쪼갠다.
- 오너 결정은 `docs/product-decisions.md` D-10~D-13에 있다. 이 문서의 '가정'과 '열린 질문'은 오너 답이 오면 갱신한다.
- 목표: 더런 회원 20여 명이 **설명 없이 바로 쓰는**, 사용성 좋은 모바일 웹앱.

---

## 1. 오너 요구 (원문 요약)

1. 실시간 채팅이 있으면 좋겠다. 참고 코드로 백오피스 채팅 화면을 말했다(아래 4장 주의 참고).
2. 그러려면 Supabase 서버를 써야 할 것 같다.
3. 리그전이 1년에 2번(상반기·하반기) 있다.
4. 리그 구성
   - 팀이 있고 팀마다 팀장이 있다. 4주 동안 진행한다.
   - 3팀이면 A-B, A-C, B-C로 서로 한 경기씩 붙는다.
   - 한 경기는 3쿼터(쿼터당 10분), 6:6이다. 교체는 자유롭다.
   - **쿼터마다 누가 뛰었는지 기록**하고, 골과 어시스트도 기록한다. 포지션 설정 등 다양한 요소가 있으면 좋겠다.
5. 06:30까지 나오는 게 기본이다. **출석 체크와 출석왕**이 있으면 좋겠다.
6. UI·UX를 깊이 고민해야 한다. 웹이므로 **뒤로가기 등이 자연스럽게** 동작해야 한다.
7. 가입·로그인은 **구글, 네이버 등으로 간단하게** 하고, 필요하면 초대 코드를 쓴다.
8. 디자인은 Mobbin(mobbin.com) 같은 레퍼런스를 참고해도 좋다.

## 2. 리그전

### 2.1 확정 (오너 답 11-15)
- **한 경기일 = 3경기(A-B, A-C, B-C) = 9쿼터.** 4주 동안 매주 1번이니 **총 12경기**다.
- **팀 구성은 팀장 드래프트**로 한다. 앱에서 **실시간 스네이크 드래프트**를 한다.
  - 순서는 1-2-3-3-2-1 반복이고, 첫 픽 순서는 앱에서 추첨한다.
  - 선수 카드에 실력(스탯 6종·포지션)과 **4주 중 참석 가능 주차**를 보여준다.
  - 시즌 시작 전에 전원이 참석 가능 주차를 입력한다.
- **기록은 누구나 한다**: 팀장, 운영진, 지정 기록원. 대신 **모든 생성·수정·삭제를 감사 기록**으로 남겨 "누가 언제 무엇을 바꿨는지" 경기 상세에서 볼 수 있게 한다.
- 팀 수는 3팀이 기본이지만 N팀(라운드로빈)을 지원한다. 팀이 4팀이면 한 경기일에 2경기씩 진행할 수 있다.
- 순위: 승 3점, 무 1점, 패 0점. 동점이면 득실차 → 다득점 → 승자승 순으로 가른다.

### 2.1-1 승점 규칙과 미니게임 (오너 추가 요구 11-15)
- 경기 승리 3점이 기본이다. 리그 4주 동안 **미니게임**(예: 승부차기, 크로스바 맞히기)도 하고, 우승 팀이 **승점 1점**을 받는다.
- **둘 다 시즌마다 커스터마이징한다.**
  - 경기 승·무·패 점수
  - 미니게임 종목(이름·설명), 종목별 우승 점수, 2·3위 점수(선택), 경기일
- 순위표에 '경기 승점'과 '미니게임 승점'을 따로 보이고 합계로 정렬한다. 동점 규칙도 시즌 설정에서 순서를 고를 수 있게 한다(기본: 득실차 → 다득점 → 승자승).
- 미니게임 결과 입력도 경기 기록과 같은 권한·감사 기록 규칙을 따른다.

### 2.2 데이터 모양

MiniGame      { id, season_id, matchday_id?, name('승부차기'), description, points: [1st, 2nd?, 3rd?] }   -- 종목·점수 시즌별 설정
MiniGameResult{ minigame_id, team_id, rank, recorded_by, at }

- 점수·순위·개인 기록은 **이벤트에서 계산**하고 따로 저장하지 않는다. 기록을 고치면 순위가 자동으로 맞는다.
- 교체는 '쿼터별 출전 명단'으로 기록한다. 분 단위 교체 로그는 v2에서 검토한다.
- 포지션: 풋살 표준(GK·FIXO·ALA·PIVO)과 기존 `formation.ts`의 PlayerPosition을 맞춘다. 쿼터 명단에서 GK를 지정할 수 있으면 클린시트·GK 기록이 나온다.
- 기존 '매주 투표 → 팀 나누기 → 경기'(D-04)와 리그는 **별개 모드**다. 같은 Match 화면 셸을 공유하되, 리그 경기는 Fixture에 묶인다.

### 2.3 경기 당일 기록 화면 (가장 중요한 화면)
- 상황: 06:30 야외 구장에서 한 손에 폰을 든 기록원(팀장 또는 운영진). **데이터가 끊기기 쉽다.**
- **오프라인 우선**으로 만든다. 기록은 기기에 먼저 저장하고 연결되면 동기화한다. 화면에 "동기화 대기 3건"을 보여준다.
- 큰 버튼 하나로 동작한다.
  - [골] → 득점자 탭 → 어시스트 탭(없음 가능) → 끝
  - 실행 취소는 5초 토스트로 한다.
- 쿼터 시작 때 출전 6명은 직전 쿼터 명단을 기본값으로 두고 탭으로 바꾼다.
- 쿼터 타이머(10분)는 보조 기능이다. 화면이 꺼져도 시각 기준으로 계산한다.
- 기록 권한: 운영진, 팀장, 지정 기록원 **모두**(오너 결정). 여러 명이 동시에 입력할 수 있으므로 다음을 지킨다.
  - 이벤트는 클라이언트가 만든 UUID로 저장한다. 오프라인 재전송에도 중복이 생기지 않는다.
  - 다른 사람이 입력한 기록이 Realtime으로 즉시 보인다. 같은 쿼터·같은 득점자의 골이 10초 안에 또 들어오면 "방금 ○○님이 입력함" 경고를 띄운다.
  - 모든 변경은 AuditLog에 남고, 경기 상세 '변경 이력'에서 볼 수 있다.

### 2.4 보는 화면
- 시즌 홈: 순위표, 다음 경기일, 득점·도움·출석 순위 상위 3명
- 경기 상세: 쿼터별 스코어 타임라인, 쿼터별 출전 명단(포지션 포함)
- 선수 카드: 시즌 출전 쿼터, 골, 어시스트, 공격포인트, 출석률, 포지션 분포
- 시즌 종료 시상: 우승팀, 득점왕, 도움왕, 출석왕. MVP는 투표(기존 투표 기능 재사용)

## 3. 출석 체크 · 출석왕

- 기준: 경기일 **06:30 KST까지 체크인하면 정시**, 그 뒤면 지각이다. 참석으로 투표했는데 체크인이 없으면 결석이다.
- 체크인 방식은 단순한 것부터 시작한다.
  1. **v1: 본인 체크인 + 운영진 확정.** 경기일 05:30~08:00에만 홈 최상단에 "도착했어요" 버튼이 뜬다. 운영진은 명단 화면에서 한 번에 확정하거나 고친다.
  2. v2 후보: 구장 QR(운영진 폰에 띄운 1분 유효 코드를 스캔), 위치 확인(선택, 실내·GPS 오차 때문에 강제하지 않음)
- 출석왕은 **연간 누적과 리그 시즌별 둘 다** 집계한다(오너 결정). 리그가 아닌 평소 주간 경기도 06:30 체크인 대상이다. 연속 정시(스트릭)도 함께 보여준다.
- 기존 `attendance` 엔티티(투표 위의 매핑)와 합친다. 투표 = 올 예정, 체크인 = 실제로 옴.

## 4. 실시간 채팅

- 기술: **Supabase Realtime**. 메시지 테이블 + RLS + Postgres 변경 구독이다. 20명 규모면 무료 한도 안에서 충분하다.
  - 백오피스 채팅은 Sendbird(유료 SaaS) 기반이라 그대로 가져오지 않는다.
  - **주의: 백오피스·chat-v2는 회사(getmiso) 저장소 코드다. 코드는 복사하지 말고 화면 패턴만 참고한다.** 참고할 패턴은 목록과 안 읽음 수, 상세, 이전 메시지 더 보기, 첨부 정도다.
- 채널
  - 클럽 전체 1개
  - 리그 팀별(시즌마다 자동 생성, 팀원만)
  - 경기일 스레드(선택)
- v1 범위
  - 텍스트, 답장, 안 읽음 수(멤버별 last_read_at)
  - 공지 고정(기존 announcements와 연결)
  - 이전 메시지 무한 스크롤
- v2 범위
  - 이미지(비공개 스토리지, 차단 #5 원칙)
  - 반응(이모지)
  - 채팅 알림은 5-1장 푸시 알림을 따른다.
- 모더레이션: 운영진이 메시지를 삭제할 수 있다. 신고 기능은 20명 규모라 생략한다.

## 5-1. 푸시 알림 (오너 추가 요구, D-14)
알림이 없으면 투표·출석·채팅이 모두 "앱을 열어야 아는" 기능이 된다. 런칭 품질의 일부로 다룬다.

- **기술: Web Push**(VAPID + 서비스 워커). 구독 정보는 Supabase `push_subscriptions`(member_id, endpoint, keys, 기기, 생성일)에 둔다. 발송은 서버(Supabase Edge Function 또는 Next.js Route Handler)에서 한다.
- **iOS 제약:** iOS 16.4 이상에서 **홈 화면에 추가한 PWA**만 푸시를 받는다. 그래서 '홈 화면에 추가' 안내(기기별 그림 안내)가 푸시의 선행 기능이다. 안드로이드 크롬은 바로 된다.
- **권한 요청 시점:** 첫 방문에 묻지 않는다. 의미 있는 순간에 이유와 함께 묻는다.
  - 예: 투표 직후 "마감 전에 알려드릴까요?"
  - 예: 첫 채팅 입장 시 "새 메시지를 알려드릴까요?"
- **알림 종류(v1):** 각각 켜고 끌 수 있게 설정 화면을 둔다.
  | 종류 | 시점 |
  |---|---|
  | 새 투표 열림 / 투표 마감 임박 | 마감 3시간 전, 아직 응답하지 않은 사람만 |
  | 경기일 아침 | 05:45 "오늘 06:30 경기" + 체크인 버튼 딥링크 |
  | 채팅 | 새 메시지는 채널별로 묶어 보낸다. 멘션은 즉시 보낸다. 방해 금지 시간 기본 23:00~05:30 |
  | 공지 | 운영진이 '중요'로 표시한 공지만 |
  | 리그 | 경기 결과 확정, 순위 변동(내 팀) |
- **딥링크:** 알림을 누르면 해당 화면 URL로 바로 간다(6장 뒤로가기 원칙과 같은 라우팅).
- **실패 처리:** 410 Gone 응답이 오면 구독을 삭제한다. 발송 결과는 로그로 남기고, 앱 안 알림함(최근 30일)과 동기화한다. 푸시를 못 받은 사람도 앱에서 확인할 수 있게 한다.
- **테스트:** 발송 로직은 유닛 테스트로 검증한다(대상 선정·방해 금지·묶음). e2e는 권한 요청 UI와 설정 화면까지만 다룬다.

## 5. 가입 · 로그인 (D-08 개정)

- **소셜 로그인으로 '누구인지' 확인하고, 초대 코드나 운영진 승인으로 '클럽 멤버인지' 확인한다.** 쉬운 가입과 명부 보호(차단 #1·#3)를 같이 지키는 구조다.
- 순서
  1. **Google + Kakao**: Supabase가 기본 지원한다. 한국 사용자는 카카오가 가장 쉽다.
  2. **Naver**: Supabase 기본 제공자가 아니다. 서버에서 OAuth를 대신 처리하는 브리지(Edge Function)가 필요하다. 수요를 보고 붙인다.
  3. 아이디·비밀번호는 소셜 계정이 없는 사람을 위한 대체 수단으로 남길지 오너가 정한다(열린 질문).
- 흐름
  1. 소셜 로그인
  2. 처음이면 "초대 코드 입력" 또는 "가입 요청 보내기(운영진 승인)"
  3. 멤버와 연결된 뒤에만 홈에 들어간다.
- 초대 코드 규격(`RUN-XXXX-XXXX`, 7일, 1회용, 멤버 귀속)은 기존 스펙 `2026-09-17-own-login-invite-design.md`를 재사용한다.

## 6. UX 원칙 (모든 화면 공통)

1. **뒤로가기가 항상 예상대로 동작한다.**
   - 탭, 시트, 모달, 필터, 단계형 폼 단계는 모두 URL로 표현한다(`?sheet=goal`, 병렬·인터셉트 라우트).
   - 뒤로가기로 시트가 닫히고, 새로고침해도 같은 화면이 나온다.
   - 목록에서 상세로 갔다가 돌아오면 스크롤 위치가 복원된다.
   - 막다른 화면이 없다. 딥링크로 바로 들어와도 상단에 돌아갈 곳이 있다.
2. **첫 화면이 지금 해야 할 일을 보여준다.**
   - 경기일 아침: "도착했어요" → "오늘 경기" → "기록하기"
   - 평일: "이번 주 투표" → "새 채팅" → "리그 순위"
3. 한 손, 엄지 영역. 주요 액션은 하단, 버튼은 최소 44px.
4. 저장 중·실패·오프라인 상태가 항상 보인다. 낙관적 업데이트에 실패하면 되돌리고 알린다.

## 9. 오너 답 (11-15 2차)
1. **팀 수는 3팀이 기본이고 4팀이 될 수도 있다. 팀 수와 상관없이 확장 가능하게 만든다.**
   - 일정 생성기는 팀 수 N, 경기일 수(기본 4), **경기일당 경기 수**(기본 3)를 입력받아 라운드로빈 대진을 고르게 나눈다.
   - 4팀이면 6대진이다. 경기일당 3경기를 넘기지 않게 주차에 나누고, 쉬는 팀이 한쪽에 몰리지 않게 한다.
   - 대진과 순서는 운영진이 생성 후 드래그로 고칠 수 있다.
2. **6명이 안 되는 경우 다른 팀에서 데려온다.**
   - 경기 단위 **임대 출전**을 둔다(Appearance에 `loan_from_team_id`). 개인 기록은 선수 본인에게 쌓이고, 경기 결과는 출전한 팀 기준이다.
   - 경기 시작 전 '인원 확인' 화면에서 부족 인원을 보여주고, 그 경기에 쉬는 팀 선수부터 추천한다.
   - 게스트(비회원) 출전도 이름만으로 허용한다. 게스트의 개인 기록은 집계하지 않는다.
3. **승점: 승 3 · 무 1 · 패 0, 미니게임은 우승만 1점.** 시즌 설정의 기본값이다.
4. **MVP는 방식이 미정이다** → 시즌 설정에서 고른다: 회원 투표 / 운영진 선정 / 우승팀 내부 투표. 투표 방식은 기존 투표 기능을 재사용한다.
5. **로그인은 소셜만 쓴다(구글·카카오·네이버).** 아이디·비밀번호는 만들지 않는다. 11월은 구글+카카오, 네이버는 12월이다. 둘 다 없는 회원이 확인되면 네이버를 앞당긴다.
