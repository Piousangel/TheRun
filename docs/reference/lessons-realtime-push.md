# 실시간 채팅 · 웹 푸시: 이전 실무 프로젝트에서 얻은 교훈 (2026-11-16)

오너가 실무에서 만든 관리자 앱(Next.js 15 + TanStack Query + zustand, 서버 NestJS + web-push + socket.io)의 **설계 교훈만** 정리했다.
- **코드는 회사 소유라 복사하지 않는다.** 아래는 원칙과 함정만 다시 쓴 것이다.
- 더런은 socket.io 대신 Supabase Realtime을 쓰지만, 교훈은 그대로 적용된다.

## 1. 웹 푸시 (D-14)
- **페이로드 모양을 한 곳에서 정한다**: `{ title, body, linkPath, notifId }`. 서버 발송부, 서비스 워커 push 핸들러, 클라이언트 래퍼가 같은 필드명을 쓴다. `linkPath`는 알림을 눌렀을 때 열 화면이다(딥링크, 브리프 6장 URL 원칙).
- **urgency와 TTL은 알림 종류마다 호출하는 쪽이 정한다. 전역 기본값으로 두지 않는다.**
  - 채팅: `urgency: high`, `TTL 60초`. 지금 오지 않으면 의미가 없다.
  - 투표 마감·경기일·공지: `urgency: high`, TTL은 길게(기본값). 오프라인이던 사람도 나중에 받아야 한다.
  - 짧은 TTL을 전역으로 걸면 오프라인 사용자의 중요 알림이 조용히 사라진다. 반대로 긴 TTL로 쌓인 채팅 알림이 기기가 돌아올 때 한꺼번에 터지는 '알림 폭탄'도 생긴다.
- **발송은 요청 처리나 트랜잭션 안에서 하지 않는다.** '보낼 알림' 행을 쌓고, 별도 작업(스위퍼)이 보낸다. 더런에서는 Supabase Edge Function + cron, 또는 DB 트리거 → 큐 테이블 구조가 된다.
- **푸시마다 타임아웃(약 10초)을 건다.** 순차 발송 중 하나가 걸리면 전원의 푸시가 멈춘다.
- VAPID 키가 없으면 앱이 죽지 않고 발송만 건너뛴다(로그 경고).
- 404·410 응답이 오면 그 구독을 비활성화한다.
- 앱 안 알림함과 푸시를 같은 `notifId`로 묶는다. 푸시를 못 받은 사람도 앱에서 볼 수 있어야 한다.

## 2. 실시간 채팅 (D-11)
- **연결 상태와 '끊김 배너'를 분리한다.**
  - 전송 가능 여부(connected)는 이벤트 즉시 반영한다.
  - 배너는 끊김이 몇 초 이상 이어질 때만 띄운다. 실제 끊김은 대부분 1~2초짜리라 즉시 띄우면 계속 깜빡인다.
  - 재연결을 반복 시도하는 동안 배너 유예 타이머를 다시 걸지 않는다. 다시 걸면 배너가 계속 늦어진다.
  - 자력 재연결을 포기한 상태는 일반 오프라인과 구분해서 "다시 연결" 버튼을 보여준다.
- **초기 연결 상태는 '연결됨'으로 시작한다.** 붙기 전 수백 ms 동안 "네트워크 끊김"이라고 잘못 알리지 않는다.
- **낙관적 전송과 에코 중복**: 내가 보낸 메시지의 서버 에코가 전송 확인(ack)보다 **먼저** 오는 일이 흔하다(실측에서 매번 40~120ms 앞섬).
  - 클라이언트가 만든 `clientMsgId`를 서버까지 보내 에코에 포함시킨다. 에코를 받으면 대기 중인 말풍선을 **같은 key로 치환**한다.
  - append하면 같은 메시지가 잠깐 두 개 보였다 사라진다.
  - 더런은 insert할 때 `client_msg_id` 컬럼을 넣는다.
- **재연결 후 백필**: 처음 연결과 '끊겼다 돌아온' 연결을 구분한다. 돌아온 경우에만 마지막으로 받은 메시지 이후를 다시 조회한다.
- **입력중 표시**:
  - 몇 초 안에 새 신호가 없으면 자동으로 끈다. 상대가 끊기면 영구로 고착된다.
  - 메시지가 도착하면 즉시 끈다.
- **접속(presence)**: 델타만 받으면 내가 붙기 전부터 온라인이던 사람을 놓친다. 연결과 재연결마다 전체 스냅샷을 받아 교체한다(Supabase Realtime Presence의 sync 이벤트가 이 역할을 한다).
- **반응(리액션)의 '내가 눌렀나'**: 서버가 브로드캐스트한 값은 누른 사람 기준이다. 수신자마다 반응한 사람 목록으로 다시 계산한다.
- 안 읽음 수는 채널마다 멤버별 `last_read_at`으로 계산한다. 쿼리 키는 팩토리로 관리한다(더런 CLAUDE.md 규칙과 같다).

## 3. 운영 습관
- 기능마다 hooks/model/ui로 나누고, 순수 로직(낙관적 갱신, 토크나이저, 권한 판정)은 따로 빼서 유닛 테스트한다.
- 회귀가 생긴 지점은 주석에 날짜와 원인을 남긴다("2026-08-11 리뷰에서 발견" 식). 다음 사람이 같은 실수를 하지 않는다.
